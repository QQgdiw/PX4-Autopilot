# Quad 待机蜂鸣与变形起落架策略

适用分支：`feature/testc4-rover-tuning`，构建目标 `zeroone_x6_hybrid`。

## 1. 待机蜂鸣

前提：操作员在四台 Bluejay 电调内关闭自主待机 Beacon，保留 DShot 命令蜂鸣能力。
PX4 不能通过本功能关闭电调自身的 Beacon；若未关闭，Rover 下仍可能自行鸣叫。

| 参数 | 默认值 | 含义 |
|---|---|---|
| `HYB_BCN_DLY` | 300 s | 连续满足待机条件后的首次蜂鸣延时，0 禁用；范围 0～3600 s |
| `HYB_BCN_INT` | 3 s | 重复蜂鸣间隔；范围 1～60 s |

参数运行时更新。只对 `is_quad_rover` 机型生效。
DShot 驱动按实际输出功能查找 Motor 1～4，而不是写死 AUX 通道号。
四个逻辑旋翼功能须都在该 DShot 实例中，输出全部为停止值，且不处于电机测试。
车辆、形态及解锁反馈须在 500 ms 内有效；必须稳定 Quad、健康、推进就绪、未解锁、
未预解锁，无急停、故障失效输出或 ESC 校准，也没有其他 DShot 命令/信息查询占用。
HX65 要求 Quad 所有权及起落架健康；允许 StableQuad，或起落架已放下的
QuadWaitAirborne（已完成变形、正在等待自动起飞）。收放运动阶段不提示。

条件中断时清零计时；停调度超过 500 ms、时钟回退或计时参数变化也重新计时。
到时直接发送一次 DShot beacon1，不排队、不修改油门、不停止正常 DShot 帧。
QGC 电机测试、人工蜂鸣/配置命令优先。普通多旋翼、普通 Rover、VTOL 不触发本功能。
“输出停止”指飞控实际下发停止指令，不代表已通过 RPM 传感器证明转子物理静止。

拆桨测试可临时设置 `HYB_BCN_DLY=10` 缩短等待，验收后恢复 300。
蜂鸣是否被现场 Bluejay 版本识别仍需实测；不要用电机旋转指令替代蜂鸣。

## 2. 请求时锁定起落架策略

只影响 HX65 双变形舵机 + HX8 起落架后端的自动起落架流程。
接受新变形请求时读取新鲜 `vehicle_status.nav_state_user_intention`，避免 Commander
临时路由后的实际模式掩盖驾驶意图；不依据命令来自 RC、MAVLink 或机载电脑来分类。

| 请求时的驾驶意图 | Rover → Quad 流程 |
|---|---|
| Manual、Stabilized、Acro、Altitude、Position、Position Slow | 放下支撑 → 上锁状态下变形 → 地面收起起落架 → 收起到位后允许解锁 |
| Offboard、Mission、Takeoff、Return 等其他模式 | 原流程：放下支撑 → 上锁状态下变形 → 允许起飞 → 新鲜离地证据稳定达到 `LG_AIR_T` 后收起 |
| 模式反馈缺失或超过 1 s | 不推断人工策略，保留原先离地后收起策略 |

人工策略下 QuadRetract 的推进所有权为 None、`propulsion_ready=false`，到位后才变为 Quad/true。
现有 Commander 解锁检查及变形命令完成 ACK 都服从该就绪状态。
人工收起超时不开放旋翼权限。完成后已解锁时，起落架位置变化本身不通过新增逻辑切断旋翼，
原有执行器健康及故障安全检查仍然保留。

变形开始后，切换人工/自动飞行模式不会重新选择策略，不触发新机构动作。
同目标重复请求也不能重选策略。下一次真正的 Rover → Quad 请求才重新采样。
因此，自动策略启动后切到 Position 手动起飞，仍是离地后收起；需要提前选好模式。
Quad → Rover 的放下、着陆去抖、上锁及机构避让流程保持不变。

`LG_AUTO_EN=0` 保持操作员独立管理起落架，位置不参与自动阶段/Ready；
起落架在线、配置和保护健康的既有安全约束不变。

## 3. 启动与恢复

- 冷启动按已确认的实际形态恢复，不因为默认飞行模式而主动收起；直接以 Quad 上电
  不等价于执行了一次人工 Rover → Quad 请求，本次保持原启动行为。
- 故障清除不会因切换了飞行模式重新选择策略，也不自动重新发起收放。
- 同一运行实例已锁定人工策略时，故障清除仍保留“未解锁必须收起到位”的条件。
  机构停在中间位置时需要明确恢复操作，不能靠 clear_fault 绕过后直接解锁。
- 过期的着陆反馈不再被当成有效离地证据，防止误收起；自动离地计时必须连续新鲜。

可查询：

```sh
hybrid_vehicle_control status
listener hybrid_vehicle_status 1
listener hx8_servo_status 1
```

CLI `gear_policy=retract-before-arm` 表示本实例已锁定人工策略；
`airborne-or-startup` 表示原自动策略或无新变形请求的启动状态。
策略未新增遥测字段；上位机继续以现有形态、故障、推进就绪、sequence 和反馈新鲜度判断许可。

实机验收需拆桨、可靠支撑机构、确认起落架收起后有稳定地面支撑和旋翼间隙：

1. 自主 Beacon 关闭后，Rover 长时间停留/行驶均无周期提示；DShot 停止帧仍保持。
2. 稳定 Quad 未解锁待机达到延时后四路提示，解锁、测试、变形、故障时不再触发。
3. 分别在 Stabilized/Position 发起 Rover → Quad：收起前不能解锁，完全到位后 Ready。
4. Offboard 流程保持带支撑起飞、可靠离地后收起；模拟过期着陆反馈不能误收起。
5. 变形途中及完成后切换人工/自动模式，机构不因模式变化折返或重新收放。
6. 人工收起失败时保持禁止解锁；清故障不自动运动、不绕过收起要求。
7. Quad → Rover、手动起落架、急停、故障保护和 QGC 电机测试回归。
8. 检查调度负载、HX 总线超时计数、切换日志及实际蜂鸣温升。不要长时间使用过强蜂鸣。
